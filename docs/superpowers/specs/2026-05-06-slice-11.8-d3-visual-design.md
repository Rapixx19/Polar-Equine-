## Context

Slice 11.7 (PR #14, merged 2026-05-06) corrected app copy — the welfare-research framing is gone, the consent checkbox is gone, activity labels are stripped of their suffixes (Riding session → Riding, Field rest → Field, Stall rest → Stall, Vet visit → Vet). Sister rides this code on a real horse the day after this slice ships.

The code is functionally complete (Phase 3 closed, Slice 11 TRIMP+zones live, Slice 11.5 recovery τ live, Slice 11.6 password auth, Slice 11.75 capture-quality guard rails) but visually it still looks like the create-next-app stone-and-white starter. The mockup at `/Users/ferdinandstraehuber/Downloads/lafattoria_d3_complete.html` (550 lines, 8 screens) defines the target: dark canvas (`#0d1410`), lime accent (`#c8f04c`), DM Sans + JetBrains Mono, D3-style charts on the saved page, riding sub-types, lunging as a top-level activity, a free-text "something else" path, and a footer-nav scaffold.

Three problem areas the prior visual misses:
1. **No sub-type granularity for riding.** A 30-min flat-work session and an 8-jump heavy course produce wildly different TRIMP and HRV signatures, but both currently land as `activity_type='riding'` with no further label. Sister's data is most useful when filtered by what the horse actually did.
2. **No "lunging" first-class option.** Lunging is on the work-vs-rest line — neither riding nor pure rest. Burying it under `other` loses the signal.
3. **Saved page is a wall of numbers.** No HR shape over time, no zone breakdown visible at a glance, no recovery context. The mockup's HR sparkline + 3 stat cards + zone-time bar + recovery card pattern fixes this with components that all already have data behind them (Slice 11 + 11.5 metrics already exist; this slice just renders them).

## Pagination utility — `web/lib/supabase/paginate-samples.ts`

Shared utility for paginated reads of `samples_hr` / `samples_acc` / `samples_ecg`. Used by:
- Saved-page HR sparkline loader (server component): pulls all `samples_hr` for one session ordered by `timestamp_ms`
- Server-side zone-time computation: same data, computed once per page render (no caching this slice)
- Future: any algo-side or admin-side bulk read of samples (this slice doesn't add a second consumer beyond the two above)

```typescript
import type { SupabaseClient } from "@supabase/supabase-js";
import type { Database } from "./types";

const PAGE_SIZE = 1000;
const MAX_PAGES = 50;

type SamplesTable = "samples_hr" | "samples_acc" | "samples_ecg";
type Row<T extends SamplesTable> = Database["public"]["Tables"][T]["Row"];

export async function paginateSamples<T extends SamplesTable>(
  supabase: SupabaseClient<Database>,
  table: T,
  sessionId: string,
  columns: string,
): Promise<Row<T>[]> {
  const out: Row<T>[] = [];
  let offset = 0;
  let pageCount = 0;
  while (pageCount < MAX_PAGES) {
    const { data, error } = await supabase
      .from(table)
      .select(columns)
      .eq("session_id", sessionId)
      .order("timestamp_ms", { ascending: true })
      .range(offset, offset + PAGE_SIZE - 1);
    if (error) throw error;
    if (!data?.length) break;
    out.push(...(data as Row<T>[]));
    if (data.length < PAGE_SIZE) break;
    offset += PAGE_SIZE;
    pageCount += 1;
  }
  if (pageCount >= MAX_PAGES) {
    console.warn(
      `paginateSamples: hit MAX_PAGES (${MAX_PAGES}) for session=${sessionId} table=${table}; result truncated at ${out.length} rows`,
    );
  }
  return out;
}
```

**Vitest cases (≥3):**
- 1000-row boundary: first page returns exactly 1000 rows → must issue second `.range()` call
- 999-row boundary: first page returns 999 rows → must NOT issue second `.range()` call (off-by-one guard)
- Multi-page: 1000 + 1000 + 500 across three calls → returns 2500 rows, three `.range()` calls

## Migration 017 — `riding_subtype` + `activity_note` + `lunging`

`web/supabase/migrations/017_riding_subtype_and_activity_note.sql`:

```sql
-- Drop the existing activity_type CHECK so we can re-add it with lunging included.
alter table sessions drop constraint if exists sessions_activity_type_check;

alter table sessions
  add column riding_subtype text,
  add column activity_note text;

alter table sessions
  add constraint sessions_activity_type_check check (
    activity_type in ('riding','lunging','grass_field','walker','stall','transport','vet','other')
  );

alter table sessions
  add constraint sessions_riding_subtype_check check (
    riding_subtype is null
    or (
      activity_type in ('riding','lunging')
      and riding_subtype in ('flat_work','light_jumping','heavy_jumping','cross_country','hack','other')
    )
  );

alter table sessions
  add constraint sessions_activity_note_check check (
    activity_note is null
    or (activity_type = 'other' and char_length(activity_note) <= 200)
  );

comment on column sessions.riding_subtype is
  'Slice 11.8: granularity tag for riding and lunging only. NULL for all other activity types.';
comment on column sessions.activity_note is
  'Slice 11.8: free-text label for activity_type=other. Max 200 chars. NULL for all other activity types.';
```
