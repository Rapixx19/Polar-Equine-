## Goal

Per build plan Slice 11.5 + `docs/algorithms/04-recovery-tau.md`:

Fit a single-exponential decay `HR(t) = baseline + amplitude * exp(-t/τ)` to the post-peak segment of each non-rest session. Write `recovery_tau_s` + a fit-quality score to `session_metrics`. τ is the canonical equine welfare/fitness signal — healthy submaximal recovery sits at 60–120s, fatigued/unwell drift past 200s.

Activity-type guard | **Skip recovery fit when `session.activity_type` is in `REST_ACTIVITIES` (defined in `service/data_types.py`).** | Spec §"Failure modes": rest sessions have no recovery curve to fit. Set both `recovery_tau_s = NULL` and `recovery_fit_quality = NULL` (truly "didn't run"). The set lives in one place (`data_types.py`) so Phase 4's `warm_up`/`cool_down` extensions only edit one constant. |
| pandas vs numpy port | **Numpy + `scipy.signal.medfilt` for the 5-sec rolling median, on a 1Hz-resampled grid.** | Same call as Slice 11. No new deps. **Resampling is mandatory** — see decision below. |
| Uniform-grid resampling pre-filter | **Add `_resample_uniform(hr_bpm, t_ms, fs=1.0, max_gap_s=10)` private helper before `medfilt`.** | H10 notifications drift 0.9–1.1s + occasional dropouts. Without resampling, the 5-element median kernel covers 4.5s in dense regions and 8s+ across gaps — τ values would drift session-to-session due to sampling jitter alone, indistinguishable from biological signal. |
| Dropout-gap rejection (v2.1) | **`_resample_uniform` raises a sentinel (or returns `None`) when any consecutive gap in `t_ms` exceeds `max_gap_s` (default 10s). `fit()` catches it and returns `_failed_result(reason="dropout_during_decay")`.** | `numpy.interp` linearly interpolates across arbitrarily long gaps, fabricating HR values that bias the curve fit toward whatever slope sits between the two endpoints. A 90-second H10 dropout mid-decay would silently produce a "successful" but garbage τ. Detect and reject. `max_gap_s` is a `RecoveryConfig` field so it's tunable per session class without code edits. |
| Logging on fit failure | **Algorithm sets `reason: str \| None` on `RecoveryResult`; route layer (`_pipeline.py`) does the `structlog.warning(...)`.** | Algorithm modules stay pure — testable without mocking structlog, importable in notebooks without log spam. Matches Slice 9's HRV pattern (algorithm raises, route logs/maps). |
| `curve_fit` exception scope | **Catch `(RuntimeError, ValueError)` only.** Returns `_failed_result(reason=f"curve_fit_raised:{type(e).__name__}")`. Other exceptions propagate. | Bare `except` hides bugs. `curve_fit` raises `RuntimeError` ("Optimal parameters not found") and `ValueError` (bad bounds, NaN inputs); everything else is a real bug we want to see. |
| `min_decay_seconds` etc. | **Use spec defaults verbatim** (60s decay, 20bpm drop, 5min fit window, 30s peak window). | Spec is the source of truth. Don't re-derive. |

## Spec gaps to flag in PR body

1. Spec uses `pandas.DataFrame`. Algo otherwise pure numpy. Numpy port adopted — same math, scipy.signal.medfilt for rolling median.
2. Spec exposes `hr_baseline_bpm`, `rmse_bpm`, `n_samples` on `RecoveryResult`. Schema only stores `recovery_tau_s` + `recovery_fit_quality`. Document the truncation as deliberate (decision B).
3. Spec §"Failure modes" notes interval workouts misfit (only the global-peak decay is captured). Acknowledged, not fixed — interval-aware τ is V.1 (per spec §"V.1 enhancement").
4. Spec talks about "orchestrator skips for `activity_type='rest_*'`." Implemented via `REST_ACTIVITIES` in `service/data_types.py` per decision D — flag explicitly so future readers don't add a duplicate guard.
5. **Spec implicitly assumes uniform-grid HR input** (`pd.rolling(5, ...)` makes a "5-element ≈ 5-second" assumption). Real H10 data is jittered. Implementation resamples to 1Hz first; addendum to `04-recovery-tau.md` calls this out so the contractor doesn't redo the math.
6. **Spec's `_failed_result()` calls structlog inline.** Implementation moves the warn call to `_pipeline.py` (algorithm purity). Spec doc addendum notes the change.

2. **`algo/algorithms/recovery_tau.py`** (NEW, ≤140 lines) — **pure module, no logging side effects**
   - `RecoveryConfig` dataclass with spec defaults; **adds `max_gap_s: int = 10`** (v2.1)
   - `RecoveryResult` dataclass — fields: `tau_s: float | None`, `hr_peak_bpm`, `hr_baseline_bpm`, `rmse_bpm`, `n_samples`, `quality`, **`reason: str | None`** (set on failure: `"insufficient_data"`, `"insufficient_decay"`, `"dropout_during_decay"`, `"curve_fit_raised:RuntimeError"`, etc.)
   - `fit(hr_bpm: NDArray, t_ms: NDArray, config) -> RecoveryResult` — numpy port; arrays in, dataclass out, no I/O
   - `_resample_uniform(hr_bpm, t_ms, fs=1.0, max_gap_s=10) -> NDArray | None` private helper — interpolates to a uniform 1Hz grid via `numpy.interp`. **Returns `None` if any consecutive `np.diff(t_ms)/1000 > max_gap_s`** so `fit()` can map to `reason="dropout_during_decay"`. Run BEFORE `medfilt`. Without it, the 5-element kernel is window-jittered by H10 sampling drift.
   - `scipy.signal.medfilt(hr_uniform, kernel_size=5)` for the smooth pass — now genuinely 5 seconds
   - `scipy.optimize.curve_fit` with bounds `([20, 5, 5], [120, 200, 600])` per spec, wrapped in `try: ... except (RuntimeError, ValueError) as e: return _failed_result(f"curve_fit_raised:{type(e).__name__}")`. **No bare `except`.**
   - `_failed_result(reason: str)` → returns `RecoveryResult(tau_s=None, quality=0.0, reason=reason, ...)`. **No structlog call here.**
   - Citations in module docstring (Art 1990, Marlin & Nankervis 2002, Buchheit 2013, Munsters 2013)

## Verification (manual gate)

1. **Spec-test parity:** the three pytest cases pass against the numpy port, deterministic with seeded RNG (`np.random.default_rng(42)`).
2. **Resampling correctness:** `test_jittered_input_resamples_correctly` proves τ stable under H10-like 0.85–1.15s jitter + 1-sample dropout (within ±15% of clean baseline).
3. **Dropout rejection:** `test_long_gap_in_decay_window_fails` proves a 90s mid-decay gap returns `reason="dropout_during_decay"` rather than a fabricated τ.
4. **Defensive catch:** `test_degenerate_input_caught` proves `curve_fit_raised:*` reasons surface — no bare `except` swallowing real bugs.
5. **Algorithm purity:** `recovery_tau.py` has zero imports of `structlog` (grep-checkable). Re-import in a notebook with no logging config → no errors, no log spam.
6. **Refactor-only commit (4a):** between commit 4a and 4b, `pytest -q` passes with identical output (proves the extraction was pure motion).
7. **Real-H10 recompute (Phase 4 closure-style gate, may be deferred):** a qualifying real-H10 ride session (HR peak ≥120bpm, ≥20bpm decay over ≥60s, non-rest activity, no >10s gap during decay) recomputes to `recovery_tau_s ∈ [60,180]`, `recovery_fit_quality > 0.5`. **If no qualifying ride yet**: PR ships as `[code-complete, real-fit-pending]` and verification waits for the first proper riding session — typically within 3-5 days of band activation. Don't fake-pass this check on a 5-min walk.
8. **Rest-session no-fit verification:** insert a synthetic `activity_type='rest_stall'` session, run /compute → row has `recovery_tau_s = NULL, recovery_fit_quality = NULL`, NO structlog warn (the guard short-circuits). Confirms decision D.
9. **Failure-mode log:** structlog warning lines visible in Railway logs when fit fails (saves freelancer debug time). Logged from `_pipeline.py`, NOT `recovery_tau.py`.
